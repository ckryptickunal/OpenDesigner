## [Unreleased]

### Added

- **Review catches what another model got past it** (2026-11-14). `engine.py review` now flags `var(--ds-...)` names that do not exist (with the nearest real one), typed font stacks and weights the system does not have. An `od-ignore` line counts as open until the owner approves its reason with `engine.py keep`, so an existing project's `od-ignore` lines fail `review --strict` until then; review lists each reason to ask about.
- **Research, hand-off and commit check need real evidence** (2026-11-14). `research add` refuses findings with no tool that read them, placeholder addresses or no day opened. `handoff yes` and `guard install` take the owner's words (`--quote`). The session-start hook names the full build loop, and DESIGN.md gives each Tailwind class its plain CSS name.
- **A shorter review and audit page** (2026-11-14). `engine.py review` now leads with the 10 biggest groups of findings (same value, same fix); `--all` lists every line. The audit page opens on the five biggest decisions and folds the rest, labels use the text font, and the header names the project. The same raw value now always gets the same token suggestion, and the note about an older system shows once a day.
- **Check-ins while you work** (2026-11-13). At the start of each session, after every five decisions and after each closed ledger round, the engine says in a few lines what changed, what is still open, whether DESIGN.md is stale and what to do next. `engine.py checkin --off` or `--every N` changes it. A project with UI code but no design system gets one short offer, once.
- **See your system as your code builds it** (2026-11-13). `engine.py audit-page --open` writes one page: each token with how often the code uses it, then every place the code and the system disagree, with the file, line and count, and up to three ways to settle each, previewed with your own values. It changes nothing; your picks come back as `OD:fix` and `OD:waive` lines.
- **Adapt your system to a site you like** (2026-11-13). `engine.py adapt <measurements.json> --open` puts your system beside the same system with a reference's corners, density, depth and type proportions. Your brand color, fonts and locked values stay yours, values you chose start unticked, and nothing is recorded until you tick what to take.
- **A ledger for every round of building** (2026-11-13). `engine.py ledger start` lists what a round covers; each item ends done, broken or skipped on purpose, with the reason and who decided. `review --strict` fails while one is open, an agent's waiver needs the owner's words before the round closes, DESIGN.md shows the ledger, and building blocks named in it now fill the coverage check.
- **Loading, empty and error states reach the system** (2026-11-13). The answers about waiting (Q-state-08), empty screens (Q-pattern-04) and error messages (Q-form-03) now make `state.*` tokens, such as when a loading sign appears and the skeleton's colours. DESIGN.md and the overview gain a States section that draws loading, empty, error and not found with your tokens.
- **llms.txt answers the questions people ask** (2026-11-13). We asked ChatGPT 36 questions and Perplexity 18, logged out. Almost only brand questions found us; one Perplexity answer cited the GitHub repo. llms.txt now opens with those questions in the askers' words, each linked to its page, and the FAQ answers three more. A feature's question appears only once its page exists.
- **A growth routine for every release and month** (2026-11-13). `docs/GROWTH-ROUTINE.md` lists the steps, the 36 fixed questions and a trend table. `python3 tools/growth_check.py` checks the build: robots.txt, sitemap, llms.txt and README facts. The search skill's `probe.md` now says how to rerun a fixed question set.
- **Empty, loading and error states in the library** (2026-11-13). 22 new parts in a States aisle: 404, 500, offline, maintenance, no access and session expired pages, four kinds of empty state, five skeletons that don't jump when data arrives, a spinner, step progress, banners, a toast with undo, a field error and a success screen. A new docs page explains when to use each.
- **Mark example files that break the rules on purpose** (2026-11-13). `engine.py exempt <folder> --why "..."` keeps a demo of mistakes out of review. Review still lists the folder and the reason, so nothing is hidden.

## [0.3.1]: 2026-11-11

A day after 0.3.0, for a design system you have already decided on. Things you removed on purpose stay removed, `engine.py review` notices tokens edited by hand or a locked decision that a merge undid, and it ends with one line: `Review: ok`, or what is left to fix. To update in Claude Code, run `claude plugin update opendesigner@opendesigner` and start a new session; the [install page](https://opendesigner.dev/docs/install/#update-it) covers the other tools.

### Added

- **Things removed on purpose stay removed** (2026-11-11). `engine.py removed add "<what>" --why "<their words>"` records something the owner took out; DESIGN.md lists it and `review` flags code that brings it back. Without their words it is recorded as assumed, still guarded. A pattern that would catch a focus ring, label, alt text, reduced-motion path or target size is refused.
- **Review guards a decided system** (2026-11-11). `engine.py review` now notices a token file edited by hand, tokens older than `state.json`, a locked decision that a merge undid, a removal that went missing, and a missing `decisions.md` or `tokens/`. Each says what to do; it never picks a value for you.
- **od-ignore takes a reason** (2026-11-11). `od-ignore: <why>` keeps a line on purpose and lists it with its reason; a reason that repeats three times prompts a question to the owner. A bare `od-ignore` is a note, and it no longer hides something removed on purpose. A reasoned one on such a line names the removal, as in "matches R-01".
- **A catalogue of states** (2026-11-11). A new template, `assets/output/STATES.md`, lists every state of a screen that shows data, with its words, tone and next step, and the rows just under, on and over each limit. The skills offer it before such a screen is built.
- **The AGENTS.md note fits the system** (2026-11-11). A first version, or a system the owner keeps loose, gets a shorter note without the strict rules, unless the owner asked for strict ones. Once the owner zooms in or tightens the rules, the next `set` or `pick` rewrites the note in place, unless someone edited it. No comment meant only for the agent reaches AGENTS.md.
- **Agent notes that route and forbid** (2026-11-11). The AGENTS.md note now says which file decides what, what never to do as part of other work, and how to settle a merge conflict in `opendesigner/`. Reports keep written, built and verified apart, and the export skill asks before replying in a Figma or Paper comment thread.

### Changed

- **Review ends with one verdict** (2026-11-11). The last line of `engine.py review` is `Review: ok` or how many things are left to fix and why, and it counts the errors `engine.py validate` finds. `--strict` exits with an error exactly when that line is not `Review: ok`.

## [0.3.0]: 2026-11-10

The second release. OpenDesigner now stays in use across long sessions and new ones, its review no longer calls code clean when it uses no tokens, text you protect in `DESIGN.md` survives every refresh, and people without a terminal get ready downloads. To update in Claude Code, run `claude plugin update opendesigner@opendesigner` and start a new session; the [install page](https://opendesigner.dev/docs/install/#update-it) covers the other tools. This release adds a start-of-session hook to the Claude Code plugin: in a project that has `opendesigner/state.json` it prints the current step, and anywhere else it does nothing.

### Added

- **Downloads that need no terminal** (2026-11-10). The README, the install page and the home page link the ready skill zips for the Claude app, so nobody has to clone and build. A new `opendesigner-chatgpt.zip` holds the five ChatGPT files and the text to paste; `tools/build_dist.py` builds it and the site serves it at `/downloads/`.
- **How to update it and how to remove it** (2026-11-10). The install page and the FAQ now say how to update OpenDesigner in each tool, how to take it out, and which files to delete to undo it in a project. The FAQ also answers what it costs.
- **Three style extractors, measured on one site** (2026-11-10). OpenDesigner's extractor, Dembrandt and Project Wallace's analyzer were scored against Primer's published tokens on primer.style. The two browser tools reported real values 84-100% of the time but got one or two colour roles wrong; reading the CSS without a browser listed 900 colours, 2% of them on the page. Our accent bug is #110.
- **Review runs without a system** (2026-11-10). With no `opendesigner/state.json`, `engine.py review` still scans the code and says "No design system is bound here", with the count of hard-coded values. It names any system found in a subfolder and the command that checks the code against it.
- **`review --strict` for commits** (2026-11-10). `engine.py review --strict` exits with an error on any finding, tokens not in charge, a `DESIGN.md` that disagrees with the code or validate errors, and its last line names each reason.
- **An opt-in commit check** (2026-11-10). `engine.py guard install` adds a git pre-commit hook that runs `review --strict`; `git commit --no-verify` skips it once and `guard remove` takes it out. The skill asks once and installs it only on a yes. It never replaces another hook or writes into a shared `core.hooksPath`.
- **Review reads the page that ships** (2026-11-09). When the folder given to `engine.py review` has fewer than three style files, it also reads the newest `index.html` (in `public/` first) and the files it loads, and lists what it skipped. It takes a single file, counts "behind the code" across the whole repository, lists the newest files first and skips `docs/`.
- **DESIGN.md checked against the code** (2026-11-09). When the code uses no color, font or text tokens, `engine.py review` says if the brand color or fonts in `DESIGN.md` appear nowhere in it, and names the ones the code uses instead.
- **`engine.py contrast`** (2026-11-09). `engine.py contrast "#767676" "#ffffff"` prints the contrast ratio, rounded down, and which WCAG minimums it meets. `--min 4.5` exits with an error under 4.5:1, for scripts.
- **One version number** (2026-11-09). Generated files and the feedback issue text show the OpenDesigner release (0.2.0), not a separate engine number.
- **A Now line that survives a context reset** (2026-11-09). `opendesigner/PROTOCOL.md` now opens with one line: the step you're on, what waits for you and the next command. Every engine command that changes the system rewrites it, and `engine.py status` prints it, so a new session picks up where the last one stopped.
- **A start-of-session hook for Claude Code** (2026-11-09). In a project with `opendesigner/state.json`, the plugin now tells Claude where the design work stands each time a session starts, resumes, clears or gets compacted: the Now line, the owner's rules count and a reminder to review. It only reads files, sends nothing, and stays silent in every other project.
- **A note later sessions read** (2026-11-09). After the first result, the skill asks once whether to write a short note for later AI sessions. On a yes, `engine.py handoff yes` adds it to AGENTS.md and writes a CLAUDE.md that imports it, even in a project with neither file. A no is remembered too.
- **Research on script sizes, corner radius and accessibility law** (2026-11-09). Seven new Decision Cards. No official size ratio exists for Devanagari, Arabic or CJK against Latin. Five studies isolate corner radius on interfaces, and none supports "rounded reads trustworthy". EU, US, UK and India law all point to WCAG Level AA, with the 2026 delay to the ADA Title II dates.
- **Share cards and llms.txt that keep up with the page** (2026-11-09). The review now warns when a page's share title or description says something its headline no longer says, and `engine.py review` warns when the share image is older than a change to the headline, hero picture, logo or brand colour. The search check now lists llms.txt lines no page states, new sections it leaves out and links to pages that are gone.
- **Nothing for reviewers on the live site** (2026-11-09). `preflight.py public` checks a build folder before a deploy for the variant picker, scripts and pictures no page uses, dev pages and local paths in served files, and the review warns about a picker it finds on a public address. The preflight checklist and the website checklist gained the launch items: the share card, llms.txt, robots.txt and an owner decision on AI-training crawlers.
- **The review notes names that say nothing** (2026-11-08). A link, button, field or image named "Read more", "Click here", "Submit", "image" or "Field 1" now gets one note in the review, with where each one is. It is a note, not an error: the text around it may already make it clear.
- **The search check finds a hidden noindex** (2026-11-08). The search skill now warns when robots.txt blocks a page that also says noindex, because search engines never get to read the noindex. It also stops asking for links to pages marked noindex.
- **AI-search advice now cites its study** (2026-11-08). The site brief's answer for AI search names the study behind it (GEO, KDD 2024): real quotes, figures and sources helped pages get used, and stuffing keywords hurt. The figures must be your own.
- **Guides that answer the question asked** (2026-11-07). The Cursor guide opens with the three things Cursor needs, a file tree, a rule file to copy and an audit-first prompt. The vibe-coded guide is now "Make a vibe-coded app look professional", with five steps and a rule list. The other guides drop repeated lines, and say what the contrast check covers.
- **Wider, calmer docs pages** (2026-11-07). The docs content column is about a third wider and running text keeps a readable line length, with more space between sections. Pages open in plain words, and commands, file paths and flags sit in a folded "For developers" section that AI tools still read in full.
- **Shorter craft pages** (2026-11-07). The motion, UX patterns, interface details, sources and design styles pages are 15 to 24% shorter, with every rule, number and source kept. They also say what is true today: 32 benchmarked systems, and the two house colour rules (known meanings keep their colours; never pure white with pure black).
- **Six new FAQ answers** (2026-11-07). The FAQ now answers how to install OpenDesigner, what it asks during setup, which files it creates, how it works with Tailwind CSS, how coding agents use DESIGN.md, and how it differs from UI UX Pro Max.
- **Get found in search and AI answers** (2026-11-07). A new skill, opendesigner-search, checks a built site for search engines and AI answer engines (SEO, AEO, GEO): which bots may read it, canonicals, titles, headings and structured data. It asks ChatGPT and Perplexity a few questions by hand, and proposes page fixes from what they searched for and cited. Nothing changes without your yes.
- **Shorter craft pages** (2026-11-07). The motion, UX patterns, interface details, sources and design styles pages are 15 to 28% shorter, with every rule, number and source kept, and tables where text compared values. They also say what is true today: 32 benchmarked systems, and the two house colour rules (known meanings keep their colours; never pure white with pure black).
- **A near-black brand builds** (2026-11-06). When the accent ramp's text step would be pure black (or pure white in dark mode), links, accent text and accent icons use an off-shade of the same hue, so the engine no longer breaks its own white-and-black rule.
- **Adding a platform raises the touch target** (2026-11-06). After `pick Q-plat-01` adds Android, a standard's 44 px touch target goes back to the engine's own 48 px, as a fresh sketch does. A value the person set is kept, and the conflict is said.
- **DESIGN.md's dial lines match the tokens** (2026-11-06). Each dial line now reports the value the tokens hold, such as 6 px corners rather than the 0 px band when nobody chose the corners, and says why the two differ. The tour shows both worked dials again.
- **Chart and table tokens for data-heavy tools** (2026-11-05). Chart colors now add a one-series brand color, status colors and a 7-step diverging ramp, each 3:1 against the page, plus axis, gridline and label colors, and every export carries them. A new table question sets striped rows, a header that stays on screen and right-aligned numbers.
- **A brand and press page from your system** (2026-11-05). `engine.py export --format brand`, also written by every build, makes `build/brand/index.html` from your tokens. It shows your logo with clear space, smallest size and do and don't examples, each colour in hex, RGB and OKLCH, your fonts, and the icon grid with your icons. Your description, facts, leadership, figures and press contact say "Not enough information" until you give them.
- **Brand colors from your logo** (2026-11-05). `engine.py sketch --logo logo.png` (or an SVG) shows up to three colors from the logo, how much of it each one covers, and the command that confirms one. White, black and see-through parts are left out, and nothing is recorded until the person picks.
- **Build writes only the exports your platforms use** (2026-11-05). `engine.py build` writes CSS and Tailwind for the web, Swift for iOS and Compose for Android, and names what it left out. Figma, Paper, DTCG and artifact files are written for every platform, and `export --format all` still writes everything.
- **More icons drawn like your own** (2026-11-05). If you have a few icons and need more, `illustrate.py icons` reads how yours are drawn (badge, glyph box, line weight, colour), ranks 24 open icon sets by how close they are, and redraws the glyphs you pick the same way. They are shown next to yours first, and each licence is recorded.
- **A site brief for sites that persuade** (2026-11-05). A landing page or marketing site now gets five questions at the broad level: the goal and how it is counted, the roles to convince, the proof, how people find it, and its kinds of pages. Each answer is drafted from your words and repo first. PRODUCT.md shows each line, or "Not enough information" with its question, and the proof is never made up.
- **Two colour rules for every project** (2026-11-05). New house standards: colours with a known meaning keep it (approved green, rejected red, pending amber, info blue, and well-known apps in their own colour), and a product never uses pure white and pure black together. `engine.py validate`, `review` and `preflight.py html` enforce the second; three library parts now draw their codes in near-black.
- **Kerning and letter spacing, checked in every project** (2026-11-05). A new guide, `preflight/references/kerning.md`, lists the type-spacing mistakes that keep coming back and how to avoid each. `preflight.py html` now flags kerning switched off, tracking in px or %, untracked capitals and words split into letters without their kerning (check 57).
- **Rules for references, samples and content** (2026-11-05). `making.md` now asks for a board of shipped samples to pick from before a new direction, live measurement instead of thumbnails, principles from a reference instead of its page, a content list that "less text" never cuts, and one system for every figure. Moving calls to action are banned.
