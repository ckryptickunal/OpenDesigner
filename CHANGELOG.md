# Changelog

All notable changes to OpenDesigner are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Detailed reasons for each product decision are in [`_coordination/DECISIONS.md`](_coordination/DECISIONS.md).

## [Unreleased]: planned as 0.1.0

The first public version: the research base, the synthesis that turns it into an interview, and the first skills, engine and host packaging.

### Added

- **Taste: the poll, the taste index and the taste card** (`skills/opendesigner/references/taste.md`).
  - The taste poll: the person rates 20 to 30 real screens from shipped products, and the result recommends the eight dials. Images stay on the person's machine; the library holds links and dial values only.
  - The taste index (`taste.py index`) merges the poll, the person's own decisions, inspirations, the style pick and feel words into a value and a confidence per dial, with red lines. The option gallery is ordered by fit and leaves out directions past a red line, and `engine.py review` flags drift.
  - The taste card: five lines under the opening sentence of DESIGN.md's Overview, and on the overview page. It shows the person's own picture of the look (`sketch --brief`), color, shape, motion and a Never list, each with where it came from. The picture and the Never list are never invented. Color, shape and motion repeat the sentences that open those sections, and the color line uses the sourced 15% accent guide (DC-L15-03), not 60-30-10. The Never list is repeated in Do's and Don'ts as taste: it warns, never fails. DESIGN.md keeps its 17 headings.
- **Making and reviewing pages** (lane L22, `research/L22-making-and-review.md`): what to do after the system exists.
  - A guide for agents, `skills/opendesigner/references/making.md`: the first draft built on the tokens, one round of feedback at a time, options on a review copy of the page with the current version kept, what stays the same between sections, checking the rendered page in the person's own window, finished interface shown inside a page, sections that hold the page, and figures drawn as graphics. It ends with the mistakes an AI builder made in that project, and what to do when the person has to repeat a note.
  - A cohesion audit template, `assets/output/COHESION-AUDIT.md`, for a page that stopped looking like one page.
  - Nine Decision Cards (DC-L22-01 to -09) from the decision trail of one marketing-site build, with 22 rows of evidence on existing cards, standards and rules, and six items for the maintainer to decide. No standard, question, default or engine code changed.
  - The main and extend skills point to the guide, and `docs/HOW-IT-WORKS.md` section 9 describes it.
- **Defaults for dense B2B work tools** (lane L23, `research/L23-b2b-work-tool.md`, from a Mobbin study of premium B2B screens and three showcase builds).
  - When Q-aud-01 is `dense`, the engine fills only what the person has not answered, set or locked. Corners are 6 / 8 / 12 px, weights are 400 / 500 / 600, and with no brand color, one blue marks selection, links and focus while the primary button can stay ink. Static cards get a 1px ring and no shadow, and floating layers keep theirs. The profile lives in `synthesis/levers.json` (`profiles`). The engine records it as `auto_default` in `decisions.md` and in `opendesigner.meta.json`, with the reason for each value and why any was skipped.
  - New for every system: row heights `size.row.sm/md/lg/two-line` in each density mode (36 / 40 / 48 / 64 at compact), `color.border.separator` for row hairlines, and tabular digits (`text.numeric.*`) on by default, as house standard STD-visual-details-02 requires.
  - Fixed: Q-aud-01 `regular` now gives the 16px body it promises (14px once Q-aud-02 or Q-layout-03 says it is a work tool). Q-dir-02's recommended default now follows Q-aud-01 (`default_follows` in `questions.json`), so accepting it no longer undoes a dense answer. Stage 14 no longer recommends sharp corners for data and developer tools. A near-black `raw.primaryActionColor` (for example `#17181c`) now stays near-black, where it used to turn periwinkle, and inverts to near-white in dark mode. Any typed action color is kept exactly when its text reads, and DESIGN.md says the buttons use it.
  - Web text floor (owner decision, 2026-10-14): when the platforms include the web, the type scale has no size under 12px. The default web system used to get an 11px small body style. iOS and Android keep 11 pt/sp.
- **Your own design-system page** (`opendesigner/overview.html`, `engine.py overview`): every `build` rebuilds it, so it grows with the system.
  - It shows the cover, brand book, colors per theme with contrast, headings h1 to h6, every text style, spacing, corners, depth, motion, core components, the 14 brand assets and a timeline of decisions.
  - Each area says **Chosen**, **Picked for you** or **Default**. Anything only a person can give (a logo, a voice guide, what the product is for) shows as **Not enough information**, with the question that fills it.
  - `build` also fills every visual template with the person's system in `opendesigner/preview/`, so nobody sees sample data.
- **The system as a Claude Design System artifact** (`engine.py export --format artifact`, also part of `build`): `opendesigner/build/artifact/project/` holds tokens in the artifact's list format, the brand book from DESIGN.md, a cover and a button preview. It is ready to publish with the Artifact tool, and the files stay in the repository.

- **Painting skill** (`skills/opendesigner-paint/`): original art and films painted in code in the brand's palette (watercolour, pointillism, charcoal, sketch, woodcut, 2D cel).
  - **The engine** is vendored from [generative-painting-skills](https://github.com/ckryptickunal/generative-painting-skills) (MIT, by Divyanshu Kumar, commit 1ff8212), by owner decision. `THIRD-PARTY.md` keeps the licence and every change:
    - three paintings ported from unattributed sketches are left out;
    - Playwright and Vite are pinned;
    - the manifest now records the real style;
    - film ids are checked;
    - the images are smaller.
  - **`paint.py brief`** turns the design system into a painting brief:
    - a style recommended from the dials, or from `Q-img-04`;
    - 8-10 palette families built only from the token ramps, each marked for which text polarity stays at 4.5:1;
    - the font licence status, the slot's size and length, and the motion, sound and identity rules.
  - **`scaffold`** creates a film project with `src/brand.js` and `BRIEF.md`. It installs nothing: npm and Chromium wait for the person's yes.
  - **`lint`** checks scenes for brand colours, seeded randomness, text painted into plates, unadapted library scenes and length.
  - **`ingest`** refuses failed exports and brings a film into the app muted, with a reduced-motion still and a pause control over 5 s (WCAG 2.2.2). It keeps a ledger and `CREDITS.md`.
  - **The standards record the exception:** this is the one skill allowed Node code, a pinned npm manifest and lockfile (installed with `npm ci`), numpy and scipy tools, and images. SPEC principle 9, REPO-PLAN, SECURITY.md and the PR-review threat table say so, and the scanner reports these files for review instead of blocking them.
  - It is offered for the H-motion, H-illus and H-motif hooks, and from opendesigner-illustrate when found art would read generic.
- **Review skill** (`skills/opendesigner-review/`): checks a built UI, yours or anyone's, the way a careful user would, and reports with evidence. It exists because a single screenshot hides what is below the fold, at other sizes, in dark mode, on hover, on Tab, in motion, and any error in spacing smaller than a few pixels.
  - `scripts/probe.js` is a read-only measurement of a running page: overflow, computed type, spacing, radius and color use, contrast (with the real backdrop), fonts and whether they loaded, targets, names, images, placeholder text, animations and what the stylesheets declare. It leaves helpers on `window.__od`: a Tab-walk recorder (ring visible, focus covered by a sticky bar), style snapshots for hover, `measure(a, b)`, `at(x, y)`, reversible stress toggles (text spacing, 200% text, long words, +40% pseudo-localized text, right-to-left), a theme/density/motion switch for OpenDesigner CSS, and pause-and-seek for animations, SVG, video, GSAP and Lottie.
  - `scripts/review.py` plans the coverage matrix and a ledger of what was and was not checked, checks probe output against the accessibility floors and, when the project has a system, its tokens (each drift names the value, how often, and the nearest token), keeps findings with how each is known (measured, operated, seen, inferred), and writes `REPORT.md`. The verdict is FAIL, INCOMPLETE or NO ERRORS FOUND in the cells checked, never "looks good". Run again on the same files, it prints what was resolved and what is new.
  - `references/cases.md` (generated from `synthesis/review-cases.json`) lists 65 ways a review goes wrong in 7 groups, each with why it is missed and how to catch it, citing 100 sources opened for the research lane (R5), re-checked by three independent fact-checking passes.
  - Two optional helpers: `scripts/capture.py` (Playwright for Python, which the skill never installs; loopback addresses only; never clicks, types or submits) runs the whole plan; `review.py serve` (127.0.0.1 only, random path) lets a browser tool load the probe in one short call and saves the result to disk. Neither is needed: pasting `probe.js` does the same job. **The standards record the exception** (2026-10-14): SPEC principle 9, REPO-PLAN, SECURITY.md and the PR-review threat table say so, and the scanner reports their Playwright imports for review instead of blocking them.
  - Tested: 58 offline tests, and 22 that drive Chrome: through the probe and `capture.py` against a page with one of every planted defect, and against each browser behaviour the references call tested (full-page capture, lazy images, finished transitions, seeking, font checks, mobile profile, focus-visible, media emulation). Run on the documentation site and a showcase app on 2026-10-14, it found a real 11 px sideways scroll at 320 px and dark-mode text at 1.14:1; four false findings seen there were fixed (an off-screen skip link, links inside a closed `<details>`, `srcset` images, a sticky sidebar).
- **Preflight skill** (`skills/opendesigner-preflight/`): the last look at anything visual (a page, video, deck or card) before it is exported or shared. It starts by asking which design system the piece was built on.
  - `references/checklist.md` has 34 yes-or-no checks in seven groups: system, type, layout, motion, truth, sound and words, and process. `references/mistakes.md` explains 35 mistakes that really happened, in the explainer videos and the showcase builds.
  - `scripts/preflight.py` (standard library, no network) reads a page's CSS, including linked token files and Google Fonts links: font sizes, sizes off the token scale, the smallest text for the medium (`web`, `app`, `watch` or `video`), tracking, fonts that never load, `<br>` in headings and layout tweens. With ffmpeg it also measures frozen time and black frames in a video, writes full-size and phone-size frames, and finds clicks and noise at the edges of voice clips.
- **Illustration skill** (`skills/opendesigner-illustrate/`): finds open-licence illustrations for a product's empty states, onboarding, error pages, sign-in, hero and feature tiles, ranks them, recolors them to the design tokens and applies them.
  - `scripts/illustrate.py` searches Openverse, Wikimedia Commons, Open Doodles, Lukasz Adam and CocoMaterial (and Iconify's multicolor sets for small spot art). It is the one skill allowed to use the network (owner decision, 2026-09-28): `search` and `fetch` call the agent-fetch sources over HTTPS, 3 MB per file at most, and `--offline` prints the requests for sandboxes without internet. It ranks by relevance, licence, format and style fit, and draws contact sheets so the model and the person judge by eye.
  - Recoloring keeps each shape's lightness and moves it to a token ramp: grays to neutral, the main hues to accent, accent2 and accent3, and skin tones are kept. It writes six variants (`themed`, `light`, `dark`, `tint`, `mono`, `swap`). The themed one follows light and dark mode through CSS variables.
  - Every SVG passes an allow-list sanitizer first: no scripts, animation, foreign content or remote loads, in markup or CSS. An independent review found four bypasses in the first deny-list version; all are now regression tests.
  - `apply` writes an SVG, HTML or React component, scopes ids, class names and CSS to the drawing, sets `aria-hidden` or a label, and keeps a licence ledger with `ATTRIBUTION.md`. The first piece applied locks the project to one illustration style.
  - **Illustration directory:** `synthesis/illustration-sources.json` (copied into the skill as `references/sources.json` by `build_data.py`) covers 44 sources (flat scenes, people, doodles, spot art and emoji, 3D, animation, pattern generators and open museum collections), each with its licence, credit rule, formats, search link, filters, tips and step-by-step navigation, and lists 12 more that were checked and left out, with the reason. Every source was checked live on 2026-09-28. `build_data.py` also renders `references/directory.md` from it. `illustrate.py directory --open` opens one page with filters and a single search box for every site, and `illustrate.py sources --q "<words>"` prints each site's search link. `references/searching.md` says where to look first, how to word a search, what each file format allows, and how an agent moves through each kind of source.
  - Sources have three access levels: agent fetches (the script searches and downloads over HTTPS: Openverse, Wikimedia Commons, Open Doodles, Lukasz Adam, CocoMaterial, Iconify), agent may browse (bots allowed, no connector), and you download (the site forbids bots).
  - `references/sources.json` records each source's licence as read on 2026-09-28. unDraw, Storyset, ManyPixels, Blush, DrawKit and SVG Repo forbid automated search or download, so the person downloads from them and `illustrate.py add` brings the file in.
  - It adapts ideas from existing tools, without copying code: from Icons8's agent skills, one style per project and a list of what each screen needs before any search; from CaesiumY's unDraw skill, a warning when a recolor changes nothing and never keeping a catalogue.
- **Learning wiki** (`learn/`, lane L19): the knowledge OpenDesigner draws from sources its owner trusts, kept as an independent, self-updating knowledge base.
  - It covers 99 sources, each with a verified analysis, and an OpenWiki Markdown wiki with 53 cross-source topic pages.
  - `learn/MAP.md` indexes it by area, standard, card and question. `learn/IMPROVING.md` explains how to change the app from it.
  - The pipeline runs through `tools/wiki.py` (`add`, `fetch`, `check`, `ingest`, `trace`, `cite-check` with TypeSafe's Jev, `standards`, `map`, `proposals`, `next`, `upstream`) and five saved workflows in `.claude/workflows/`.
  - OpenWiki is pinned in `learn/openwiki.lock.json` and checked weekly in CI.
  - The rules are in `docs/KNOWLEDGE.md`.
- **House standards** (`synthesis/standards.json`, v3): 455 rules from the owner's non-negotiable sources (Emil Kowalski's writing and skills, Sonner, animations.dev, Vaul).
  - Each rule is citation-checked and reviewed.
  - The engine applies and locks them for each project's platforms and stack, including new tokens such as the 0.97 press scale.
  - Commands: `engine.py standards [--update]`, and `standard override|restore|add|remove`, which covers project standards, per-path overrides and `--beats`.
  - Constraints stop values that break a rule (no ease-in curves on UI; UI motion stays under 300 ms unless a standard names the exception).
  - The interview skips questions a standard settles and refuses options that break one.
  - `review` flags code that breaks a standard. DESIGN.md carries a short summary, with the full list in `opendesigner/standards.md`.
- **Decision Cards from the wiki:** 164 in `research/L19-learning-wiki.md`, with 253 proposed changes and 75 conflicts with older research.
  - Three cards are adopted so far; the rest are listed as pending in `synthesis/QUESTIONNAIRE.md` for lane L20.
  - "Now / As it grows" notes for 30 high-impact questions appear under each option.
- **Research search:** `tools/jev_nav.py find` also searches the house standards and ranks with BM25. It judges each card by its recommended default and marks older cards the house supersedes.

### Fixed

- **Renaming a system no longer leaves an old export behind.** `export --format dtcg` removed nothing, so after `set name` the folder held both `<old>.resolver.json` and `<new>.resolver.json`. It now keeps only the current one (found while rebuilding showcase hero 02).
- **Accessibility claims match the engine.** The docs, the spec, the GTM facts and the interview no longer say every system gets reduced-transparency or high-contrast modes. The engine's modes are theme, density and motion. A system with glass gets a solid fallback for each glass surface, which the CSS export swaps in under `prefers-reduced-transparency` or `prefers-contrast: more`, now also when the device is in dark mode. House standards are v3: only the conflict note of `STD-accessibility-motion-12` changed.
- **A brand color the person typed is never replaced** (`brand/showcase/STRESS-TEST.md` findings 1, 6 and 19). The sketch used to swap light brands for a dark shade so white text would pass: yellow #FFE500 became olive #847600, lemon #FFE45C became #877400 and lantern gold #FFC24B became #996d00, and the message said "I picked an olive".
  - A hex given with `--brand` stays the person's, even under `--delegated all`. It counts as the model's pick only when `brand` is named.
  - The brand and secondary colors (`raw.secondaryColors`) stay exact on their fills, with white or dark text, whichever reads. In dark mode, each stays exact when the dark text of dark-mode buttons reads on it. Otherwise dark mode uses a lighter shade that keeps the color's own chroma, for the brand and the secondaries alike.
  - When neither white nor dark text reads on a color, fills that carry text use a readable shade, and the exact color stays in its seed token (`color.brand.seed`, and the new `color.accent2.seed` and `color.accent3.seed`) for logos, large areas and anything without text. The message says so in plain words, including the dark-mode shade.
  - `pick Q-color-01 keep-hex` now puts back a hex that an older sketch replaced. It never undoes a color set since then.
