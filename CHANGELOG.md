# Changelog

All notable changes to OpenDesigner are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Detailed reasons for each product decision are in [`_coordination/DECISIONS.md`](_coordination/DECISIONS.md).

## [Unreleased]: planned as 0.1.0

The first public version: the research base, the synthesis that turns it into an interview, and the first skills, engine and host packaging.

### Added

- **The component library, reworked to a craft standard** (owner, 2026-10-23: "very congested", "the smiley icon ... is not properly done", "use sample images from Unsplash"). `assets/library/CRAFT.md` sets the rules: roomy token spacing, neutral colour with one accent, Lucide icons (ISC), real free Unsplash photos where a picture belongs (`photos.json`, 119 photos and 80 portraits, each verified), and phones that stack instead of squeezing. All 82 parts were rebuilt to it, reviewed by four fresh reviewers and fixed; every person has one portrait that fits their name (`people.json`). The shop opens in the calm Nordic look, credits each photographer on the part's page, loads card previews lazily as you scroll (layout on load from 830 ms to 70 ms), and leads with the parts most likely to draw people in. `library.py check` gains rules for photos, scripts that look elements up by id, rows sized to the target floor, hard bottom ledges and attributes the site's scripts read.
- **Product analytics with PostHog** (owner, 2026-10-23 and 2026-10-24). `site/static/ph.js` loads PostHog's US cloud through `/ingest/` on the site. By default it is cookieless (a daily server-side hash counts visitors) and records where each visit came from (referrer, `utm_` tags, `ref=`, landing page) and named library events for funnels. A small card asks once for consent to session recording; only after Allow does PostHog keep an anonymous id and record the visit, with every input masked and the booking page never recorded. `docs/PRIVACY.md` says what is counted.
- **Every push to main goes live by itself** (owner, 2026-10-23: "so that I do not have to keep doing this again and again"). `site/autodeploy.py` runs every 2 minutes on the maintainer's Mac. When `main` on GitHub moves and has been still for 5 minutes, it builds and checks the site in the clean deploy worktree and publishes it with `site/deploy.py`, which checks the key pages before the domain switches over. A failed deploy leaves the site as it was, and the Mac shows a notification. It runs on the Mac because GitHub Actions is disabled for the owner's account and Vercel can't build this site from a plain clone.
- **A Taste Index of a look you love** (owner, 2026-10-23: the reel's Taste Index "is the way taste indexes should be implemented"). `opendesigner-extract`'s new `taste_index.py` writes a full description of one look from a few pages of a site, or a screenshot: a one-line picture, 5 to 7 principles with their reasons, every colour with its job and share of the page, type roles with exact font names and free substitutes, component rules, motion, voice as counts, a Never list, a CSS variable for every value and a live specimen page. Every line says measured or inferred. By owner decision it keeps the site's exact colours and font names when first shown, with a notice that what you keep is your responsibility; logos, brand names, images and copy never go in, and font files are never shipped. A project can hold several; each nudges the taste dials as an inspiration, and the system follows one only when the person chooses it (`taste_index.py use`, which also asks exact fonts or free substitutes). When someone asks to copy a brand's look, the agent offers a Taste Index of it (owner, 2026-10-23); the logo, name, images and copy are still declined. SPEC 5.4, AGENTS.md, the extract skill, the guardrails, HOW-IT-WORKS, taste.md and both FAQs say so.
- **Six measurement fixes in reference intake**, found by reading typesafe.ai and davecto.com against the reel's own indexes. Borders drawn by `::before`/`::after`, windows, frames and hard shadows are seen (typesafe's depth 56 with soft shadows is now 8 with 1 px windows). Loops that always run are kept apart from UI transitions and easing is kept (its energy 100 is now 35). The browser's link blue, wrapper links and error-state focus rules no longer win the accent (davecto's accent is its teal, not its error red). Density reads the space between text and blank bands, not only body size (davecto 78 compact is now 29 spacious). Colourfulness reads how much of the page is coloured. Section colours and their share of the page are recorded. Several pages of one site merge, and cookie banners are left out.
- **Preview a value before recording it** (2026-10-23). `engine.py set <path> <value> --dry-run`, and `pick <Q-id> <value> --dry-run`, run the same checks a real set runs and print what it would report, plus each token's old and new value (named roles first, each mode that changes), any check the value would add or clear, and the command that records it. Nothing is written: state.json, decisions.md, DESIGN.md and the journey log stay byte for byte as they were. In the extend-rounder agent eval, an agent compared roundness 55, 60 and 65 with real sets, which added decisions the person never made to their append-only log. The extend skill now previews values and records only the one the person picks.

- **Review skill** (`skills/opendesigner-review/`): checks a built UI, yours or anyone's, the way a careful user would, and reports with evidence. It exists because a single screenshot hides what is below the fold, at other sizes, in dark mode, on hover, on Tab, in motion, and any error in spacing smaller than a few pixels.
  - `scripts/probe.js` is a read-only measurement of a running page: overflow, computed type, spacing, radius and color use, contrast (with the real backdrop), fonts and whether they loaded, targets, names, images, placeholder text, animations and what the stylesheets declare. It leaves helpers on `window.__od`: a Tab-walk recorder (ring visible, focus covered by a sticky bar), style snapshots for hover, `measure(a, b)`, `at(x, y)`, reversible stress toggles (text spacing, 200% text, long words, +40% pseudo-localized text, right-to-left), a theme/density/motion switch for OpenDesigner CSS, and pause-and-seek for animations, SVG, video, GSAP and Lottie.
  - `scripts/review.py` plans the coverage matrix and a ledger of what was and was not checked, checks probe output against the accessibility floors and, when the project has a system, its tokens (each drift names the value, how often, and the nearest token), keeps findings with how each is known (measured, operated, seen, inferred), and writes `REPORT.md`. The verdict is FAIL, INCOMPLETE or NO ERRORS FOUND in the cells checked, never "looks good". Run again on the same files, it prints what was resolved and what is new.
  - `references/cases.md` (generated from `synthesis/review-cases.json`) lists 65 ways a review goes wrong in 7 groups, each with why it is missed and how to catch it, citing 100 sources opened for the research lane (R5), re-checked by three independent fact-checking passes.
  - Two optional helpers: `scripts/capture.py` (Playwright for Python, which the skill never installs; loopback addresses only; never clicks, types or submits) runs the whole plan; `review.py serve` (127.0.0.1 only, random path) lets a browser tool load the probe in one short call and saves the result to disk. Neither is needed: pasting `probe.js` does the same job. **The standards record the exception** (2026-10-14): SPEC principle 9, REPO-PLAN, SECURITY.md and the PR-review threat table say so, and the scanner reports their Playwright imports for review instead of blocking them.
  - Tested: 58 offline tests, and 22 that drive Chrome: through the probe and `capture.py` against a page with one of every planted defect, and against each browser behaviour the references call tested (full-page capture, lazy images, finished transitions, seeking, font checks, mobile profile, focus-visible, media emulation). Run on the documentation site and a showcase app on 2026-10-14, it found a real 11 px sideways scroll at 320 px and dark-mode text at 1.14:1; four false findings seen there were fixed (an off-screen skip link, links inside a closed `<details>`, `srcset` images, a sticky sidebar).
- **Preflight skill** (`skills/opendesigner-preflight/`): the last look at anything visual (a page, video, deck or card) before it is exported or shared. It starts by asking which design system the piece was built on.
  - `references/checklist.md` has 34 yes-or-no checks in seven groups: system, type, layout, motion, truth, sound and words, and process. `references/mistakes.md` explains 35 mistakes that really happened, in the explainer videos and the showcase builds.
  - `scripts/preflight.py` (standard library, no network) reads a page's CSS, including linked token files and Google Fonts links: font sizes, sizes off the token scale, the smallest text for the medium (`web`, `app`, `watch` or `video`), tracking, fonts that never load, `<br>` in headings and layout tweens. With ffmpeg it also measures frozen time and black frames in a video, writes full-size and phone-size frames, and finds clicks and noise at the edges of voice clips.

### Fixed

- **The library's activity part no longer copies Apple** (2026-10-24, found by a copy review of the GTM videos). `activity-rings` drew three nested Move, Exercise and Stand rings and said "close your Move ring": Apple Activity's look and words, against the rule that references give structure, never identity. It is now `daily-goals`: steps, active minutes and water, each a flat bar in the system's one accent with a check when it's met, a count of goals met, and a week of small bars. The old page and file addresses redirect.
- **A corner radius between the steps builds** (2026-10-23). `engine.py set radius.control 10` was recorded, but the tokens pointed at a 10 px step the scale did not have, so the next build stopped in all 12 mode combinations and nothing exported. The same happened for `radius.container`, `radius.overlay` and `radius.detail`. A radius between the steps now gets its own step on the scale (as `raw.borderWidths` does for border widths), and the small-control radius drops to the step below it (8 for 10). `set` and `standard add` refuse a value that cannot be a radius before anything is written, and name the steps: a negative or fractional number, another unit, or "full" for cards and dialogs ("full" stays for controls and tags; "10px" is stored as 10). `icon.defaultSize` takes only 16, 20 or 24; before, 19 was recorded and the tokens silently used 20. A bad radius recorded by an older version builds with the Roundness dial's value, and validate says so.
- **Two agent eval graders** (2026-10-23). `no-identity-copy` now checks that the OpenDesigner skill ran, so a run where it never starts shows as that, not only as a copied brand. `extend-rounder`'s "says what changed" no longer fails a reply for listing the files the rebuild wrote again, corner sizes that follow from the same setting, the engine's log entry for that setting or a version stamp; it still fails a reply that says another design choice changed. Run once each after the change: both scored 1, with the skill used.
- **Agent evals run the cases you ask for** (2026-10-22). `tools/agent_evals.py` takes several cases or tags at once (`--case 'export*,extend*'`, `--tag smoke,guardrail`, or the flag repeated) and stages only those, so `claude plugin eval` runs exactly them. `--list` shows which cases match and their tags, at no cost. A filter that matches nothing now stops with that list and exit 2. Before, it reported "overall 0" and exited 0: on 2026-10-22 two runs silently ran nothing, one with a brace list inside quotes and one with `[ceons]*`, a pattern `claude plugin eval` does not match but Python's `fnmatch` now does.

- **The option gallery is never empty** (2026-10-23). Hating native-looking screens in the taste poll drew a red line on brand presence, a dial none of the three directions sets, so all three were hidden while one was still recommended. A red line now only judges the dials the directions differ on; a dial they all share is flagged by `engine.py review` as drift instead. If every direction is still past a line, all are shown with a warning that names each line. The recommendation is always a direction that is shown, and `taste.py fit` follows the same rule.

- **Apple's letter spacing and corners now change the files they promise to** (Q-type-13 `size-table`, Q-shape-04).
  - Letter spacing: `size-table` used to give the same coarse bands as the default. It now gives Apple's SF Pro tracking table from the HIG (64 sizes from 6 to 96 pt, `levers.json` `formulas.type.tracking.sfPro`), interpolated between sizes. A face other than the system font takes the table only up to 19px, because from 20 pt Apple loosens SF Pro Display and other faces would look loose. Uppercase labels stay at least +0.05em. Systems built before this keep their spacing unless the person chose the table.
  - Corners: Q-shape-04 used to be recorded only. `squircle-enhance` now adds Apple's continuous corner to the CSS and Tailwind exports where the browser draws `corner-shape`. `continuous` and `squircle-enhance` give Figma corner smoothing 0.6, and the Swift export uses `.continuous` (`Radius.shape(...)`). DESIGN.md says which platform draws which.
  - The web corner is `superellipse(1.35)` at 1.22 times the radius. It follows SwiftUI's own curve within 0.4% of the radius (`tools/fit_corner.py`, `formulas.radius.continuous`). The `squircle` keyword the docs recommended is 18.7% of the radius off, squarer than iOS. A plain circular arc of the same radius is within 1.4%, so browsers without `corner-shape` lose little.
  - The website follows the same rules: a build step gives each text size up to 19px its tracking value. Before, 37 of 108 text styles had the wrong spacing, because inherited letter spacing goes wrong when a child changes size. Its corners use the fitted shape, and only the boxes that get the shape are enlarged.
  - The Q-shape-04 options no longer break at the colon in `corner-shape: squircle`, which had split one option's label in two.
- **Renaming a system no longer leaves an old export behind.** `export --format dtcg` removed nothing, so after `set name` the folder held both `<old>.resolver.json` and `<new>.resolver.json`. It now keeps only the current one (found while rebuilding showcase hero 02).
- **Accessibility claims match the engine.** The docs, the spec, the GTM facts and the interview no longer say every system gets reduced-transparency or high-contrast modes. The engine's modes are theme, density and motion. A system with glass gets a solid fallback for each glass surface, which the CSS export swaps in under `prefers-reduced-transparency` or `prefers-contrast: more`, now also when the device is in dark mode. House standards are v3: only the conflict note of `STD-accessibility-motion-12` changed.

  - `pick Q-color-01 keep-hex` now puts back a hex that an older sketch replaced. It never undoes a color set since then.
