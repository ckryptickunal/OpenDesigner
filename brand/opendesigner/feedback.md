## F-001 · 2026-10-14 · bug
engine.py set accepts unknown dial ids without an error: 'set dials.colour 62', 'set dials.brand 80' and 'set dials.notADial 5' all succeed and write junk keys to state.json, while the real dial (colorfulness) stays at its default. DESIGN.md then reports Brand presence 80 (alias?) but Colorfulness 36, so the mistake is easy to miss. set should reject an unknown dials.* id and list the 8 valid ids.

A supplied brand hex should stay the brand color (chosen), with the accessible shade derived as the accent and the change stated in plain words.
