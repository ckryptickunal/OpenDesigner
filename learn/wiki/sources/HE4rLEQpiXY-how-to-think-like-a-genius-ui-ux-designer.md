# How to think like a GENIUS UI/UX designer

## Summary

Kole Jain argues that strong UI/UX designers focus on making things work for the user rather than on making them look good, and treat web design as a story that guides someone to an action. Using an Airbnb-like vacation rental flow, he shows how to start from user intent (a search bar first, then listings and filters for people who want to browse) and to expand functionality only as intent expands. He recommends following the layouts users already expect, choosing and structuring content for how people scan it and for imperfect real content, and using animation only when it adds clarity or function, with progressive disclosure and a Load more button over infinite scroll as examples. He closes by saying a design system should reflect the team's values and size, that developing it (rules, spacing, type scales, interaction patterns) is often more critical than the design itself, that it is a shared language rather than a way to make everything look the same, and that its rules should be broken only on purpose. For someone building a design system, this gives a user-intent-first process, content stress tests, a functional-motion stance and a way to size the system to the team.

## Key Ideas

- Good design focuses on making things work brilliantly for the user, not only on making them look good.
- Think of web design as a story that guides someone to an action; extra flare like 3D graphics or smooth scrolling can get in the way.
- Start from user intent: if people come to search, the search bar is the natural starting point, augmented with useful inputs.
- A site can serve more than one intent, such as searching and browsing, and each intent adds its own functionality.
- Fonts, colors and icons change the aesthetics but do very little to change functionality.
- Users expect certain layouts after decades of websites: top-to-bottom, left-to-right flow, navigation at the top, easy-to-find calls to action.
- Conventional layouts are easier to extend with new sections and to make responsive; uniqueness comes from micro interactions and features.
- Designing around content has two steps: decide what content to show, then structure it so imperfect content still works.
- Animations should add clarity or functionality; his old portfolio, whose animations didn't do anything, is his example of what not to do.
- Progressive disclosure shows what the user needs and reveals more as it is required.
- A Load more button is preferable to infinite scroll because it gives control and lets users reach the footer.
- Buttons should almost always have a small animation, while scrolljacking should be used very sparingly, if ever.
- A design system should match the team: lightweight and easy to scrap for a lean startup, massive and deeply defined for many products.
- Building the system (rules, spacing, typography scales, interaction patterns) is often more critical than the design itself.
- A design system is a shared language, not a way to make everything look the same; break its rules with intention.

### Process

1. Find the user intent: Ask why the user is there (e.g. to search for accommodation) before thinking about icons or card layouts.
2. Build the element that serves it: Start with the natural element for that intent, such as a search bar, then augment it with useful inputs like destination, number of travelers and dates.
3. Serve additional intents: For users who want to browse, display listings and add filtering UI; expand functionality only as intent expands.
4. Leverage existing layouts: Let information flow top to bottom and left to right, keep navigation at the top and make calls to action easy to find; add uniqueness through micro interactions or features.
5. Decide which content to display: Use how the user will interact to pick the information shown, e.g. location, rating and price on cards, details on click.
6. Structure the content for imperfect cases: Test with long names and bright images; truncate long names and add a circle behind icons to guarantee contrast.
7. Add functional animation: Animate only what adds clarity or function: menus and search bars that reveal on demand (progressive disclosure), small button animations; avoid scrolljacking.
8. Build a design system that fits the team: Define rules, spacing, typography scales and interaction patterns at a size that matches the team, and break the rules only with intention.
