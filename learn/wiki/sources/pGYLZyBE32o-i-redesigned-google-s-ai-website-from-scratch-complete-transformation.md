# I Redesigned Google's AI Website from SCRATCH (complete transformation)

## Summary

Kole Jain redesigns the Google Gemini landing page from scratch, narrating each section and the choices behind it. He starts from inspiration (Microsoft Copilot, OpenAI, Google Chrome and other Google products), picks a visual recipe of mesh gradients, noise and fully rounded corners, and merges three separate Google landing pages into one. Along the way he shows concrete moves: a typeable search bar instead of a plain button as the hero call to action, a bento section, a gradient trick for adding color to dark mode, hover effects that blur, enlarge and reveal text on image cards, and a privacy section. He also shows iteration openly, walking through about four call-to-action layouts before one felt right, and avoids reusing the same layout twice on one page. For a design system, it gives a worked example of a marketing-page process and of where gradients, hover states and icon choices sit in an AI product's visual language.

## Key Ideas

- Start a redesign by collecting inspiration from competitors and sibling products, then borrow and adapt layouts.
- Mesh gradients are called pretty much synonymous with AI; the redesign pairs them with a healthy dose of noise and fully rounded corners.
- A typeable search bar as the hero call to action gets the visitor into an action, which the author says makes them more likely to follow through.
- Replace decorative background shapes with a product-native animation, such as the chatbot's thinking loader, when the brand style is clean.
- Merge redundant landing pages that sell the same thing into one page built around a few key points.
- Add color to a dark mode by using a darkened two-color gradient of the primary colors as the background, optionally with some noise, but not so much the site looks like TV static.
- Image cards can reveal more on hover by blurring the image, enlarging it and popping up extra text.
- Hide options that matter to few visitors (Enterprise) behind a small button on each plan instead of giving them a section.
- A good layout carries the design before any animation is added.
- Iterate through several layouts for a key section; the final CTA came after about four attempts.
- Do not reuse the same layout for two sections of one page.
- Products that handle user data need a privacy section, and icon metaphors should match the brand (shield vs lock).
- When the hero search bar works, reuse it in the final call to action, with decorative prompt cards moved to the sides.
- For clean, simple icons, search Flaticon by interface icons.

### Decisions it informs

- What should the hero call to action be on an AI product landing page?
  - Plain button: A standard click-through; the author finds it less engaging and less cool-looking. When: Not recommended here.
  - Typeable search or prompt bar: Visitors start typing, which redirects them to log in; they are already engaged in an action. Mesh gradients go where a search icon could have been. When: When the product itself is a prompt or search box, as with an AI chatbot.
  - Recommendation: Typeable search bar: the user is already engaged in an action and more likely to see it through, and it looks cooler than a plain button.
- How do you add attention to a clean hero section?
  - Background shapes: Looked messy against Google's typically clean style. When: Not for a clean brand.
  - Product-native animation (chatbot thinking loader at the bottom of the header): Looks like the AI is actually thinking; an eye-catching animation. When: When the product has a recognisable loading or working state.
  - Recommendation: The chatbot loading animation, because background shapes looked messy.
- Where should gradients be used on an AI product site? (`Q-color-25`)
  - Mesh gradient on the hero search bar: Signals AI; mesh gradients are called synonymous with AI. When: Hero and key interactive elements.
  - Darkened two-color gradient as the dark-mode background: Adds subtle color to a dark page using the brand's primary colors. When: When dark mode feels colorless.
  - Gradient stroke on the purchase card and on hover: Highlights the CTA card and adds brand color on interaction. When: For the plan you want people to pick, and hover states.
  - Gradient icons: The author did not like them and switched to solid Google blue. When: Rejected in this redesign.
  - Recommendation: Use gradients on the hero, backgrounds, CTA strokes and hover strokes, but not on icons.
- Which layout should a marketing feature or showcase section use? (`Q-layout-05`)
  - Bento layout: Cards with headers, short descriptions and integrated diagrams or product UI. When: Features section with several distinct capabilities.
  - Text on the left, image on the right: The author calls it the lame default. When: Fallback when a fancier layout does not fit the content.
  - Multi-image showcase borrowed from the Chrome site: Several images (a fourth added) with chatbot elements so it feels like a real chatbot. When: Showing off image generation or visual output.
  - Layout that breaks the box by extending off the page: Cards run off the edge of the page, with navigation to move through them. When: An explore or browse section with many items.
  - Recommendation: Bento for features, the Chrome-style showcase for images, and the off-page layout for exploring; the first image layout was dropped because it did not leave enough room for the content.
- How should image cards respond on hover?
  - Zoom-in effect: A zoom-in effect the author loves on the Chrome website; it gave him the idea of a hover-driven section. When: The starting idea for a hover-driven section.
  - Blur, enlarge and reveal text: The image blurs and grows while additional text pops up; a classy interactive effect. When: When cards need to hold more information than fits at rest.
  - Recommendation: Blur the image, make it larger and pop up additional text (the Accenture-style effect).
- Where should a rarely needed plan (Enterprise) go?
  - Its own section or card: Takes space for information most visitors do not need. When: Not recommended here.
  - A tiny button on every plan: Keeps the plans compact while still offering the path. When: When the option is irrelevant to most visitors.
  - Recommendation: A tiny button on all the plans, because the Enterprise part is not useful for about 98% of visitors.
- How should the final call-to-action section be laid out?
  - Prompt cards with a typeable card at the bottom: Felt weird. When: Rejected.
  - Typeable card just below the text: The spacing did not feel right. When: Rejected.
  - Card collapsed into just the search bar: Still did not feel right. When: Rejected.
  - Centered layout: Better. When: Intermediate step.
  - Centered search bar with the prompt cards moved to the sides as gradient decoration: The final version; the cards are there for decoration. When: Chosen.
  - Recommendation: Centered layout with the decorative prompt cards moved to the side and given a gradient, echoing the search bar from the header.
- What visual should carry a privacy section?
  - Lock icon: Feels more like Apple. When: Apple-like brands.
  - Shield icon: Feels more like Google. When: Google-like brands.
  - Grid with isometrics and blue concentric circles: Replaced a result the author thought looked lame; adds more visual interest. When: When the plain icon treatment looks lame.
  - Recommendation: The shield for brand fit, then a grid with isometrics and blue concentric circles to make it better.

### Process

1. Audit the current and competitor sites: Look at OpenAI, Microsoft, Midjourney, Gemini and the Chrome landing page and note what is weak (lopsided layout, too many tabs and videos, neglected page) and what works.
2. Gather inspiration: Pull from Microsoft Copilot, OpenAI, Google Chrome and other Google products.
3. Pick the visual recipe: Choose mesh gradients, a healthy dose of noise and fully rounded corners.
4. Plan the page roadmap: Draft the section order (partly generated with Gemini, loosely following Microsoft's landing page) so three separate Google pages condense into one.
5. Design the header: Typeable search bar CTA with a mesh gradient, a punchy headline, the Google logo on a white background and the Gemini star, plus the chatbot loading animation for attention.
6. Build each section by borrowing and adapting: Bento features with product UI and diagrams, an image showcase, merged plans with hover effects, an explore section, privacy, CTA, blog and footer.
7. Consolidate redundant content: Scroll through overlapping pages and keep only the key points (cost, better AI, document uploads).
8. Iterate on layouts: Try multiple layouts for a section (about four for the CTA) and keep adjusting until spacing and balance feel right.
9. Avoid repeating layouts: If a layout is already used on the page, choose another for the next section.
10. Close with a footer that mirrors the header: Base the footer on the Gemini website's header and use the same element as the page header, swapping the Google logo for the Gemini one.
