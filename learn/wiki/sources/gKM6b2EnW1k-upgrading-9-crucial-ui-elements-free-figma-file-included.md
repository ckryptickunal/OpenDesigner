# Upgrading 9 CRUCIAL UI Elements (free figma file included)

## Metadata

- Video ID: `gKM6b2EnW1k`
- Channel: Kole Jain
- Published: 2024-06-18T20:46:35Z
- URL: https://www.youtube.com/watch?v=gKM6b2EnW1k

## Summary

Kole Jain redesigns nine common UI elements (a mobile tab bar, a chart, UI cards, pricing cards, stickers, a sign-up modal, a footer, chips and an image carousel), fixing both how they look and how they work. Most fixes are small, concrete moves: line up the tab bar's add button with the other icons and give every tab an active state, stop curving chart lines, make a repeated card the link instead of adding a button, put form labels above inputs, and keep a footer simple when a site only has a handful of links. He also gives a few exact recipes, such as chip vertical padding at half or a quarter of the horizontal padding, a 4 px grid for sign-up and login modals, and an input style with an off-white fill and a 40% opacity stroke. For a design system, the video supplies component-level defaults and rules (tab bar, chart, card, pricing card, form field, footer, chip, carousel) and several either-or choices that can be shown as visual samples.

## Key Ideas

- Elements copied from Dribbble often look good but fail on usability; each element needs both its UI and its UX checked.
- A tab bar's raised, circled add button draws attention to the tab people use least; drop it into line with the other icons.
- Color is only useful if it can be seen: inactive icons and background differences need enough contrast.
- Every tab, including add and profile, can have an active state, and active states are the place to use brand color in a nav bar.
- Whether a tab bar needs labels depends on how obscure its icons are; if there are labels, they must be dark enough to read.
- Smoothed, curved chart lines hide where the data actually sits; grid lines, markers, a time-frame switcher and a legend make a chart readable.
- When cards repeat, the whole card can be the link, with an arrow that fades in on hover; a card with a specific action keeps its button.
- A pricing card reads better with a plan name and description, check marks instead of bullets, honest billing text and an actionable button label.
- Stickers break out of boxy layouts and are a place to be creative with shape, display fonts, outlines and hard drop shadows.
- Labels used as placeholder text disappear while typing; labels belong above the input, and the placeholder should be a real example.
- Most sites have 3 to 5 footer links, so a simple centered footer beats copying the many-column footers of Apple or Linear.
- Chips differ from buttons: they are thinner vertically and almost never use the primary call-to-action color.
- A carousel needs navigation that shows how many images there are and stays visible whatever image is behind it.

### Rules and practices

- **should** (components, all): Do not raise the tab bar's add or create button above the bar in a circle; drop the icon into line with the other tab icons and keep all icons aligned. Why: People use all of the other tabs most of the time, so the one they use least should not stick out. [let's drop the icon down and get rid of the circle]
- **should** (color, all): Keep inactive tab bar icons clearly visible; show the active tab with its own active style instead of fading the other icons out. Why: The active state already shows which tab is selected, so the other icons do not need to be impossible to see. [we don't need to make the other icons impossible to see]
- **should** (color, all): Use background colors that differ enough to be noticed; if two surfaces are meant to look different, give them visible contrast. Why: The whole point of using colors is that people can see them; in the original, nobody could tell the backgrounds were different. [there are fact different background colors here neither could I]
- **should** (components, all): Give every tab an active state, including the add tab, by using an icon that has an active version. Why: Swapping the plus icon for one with an active version lets that tab show when it is selected too. [we can now have an active state for that too]
- **consider** (components, all): Use the person's profile picture as the profile tab icon when they have uploaded one. Why: The source suggests swapping the generic user icon for the uploaded profile picture. [Swap this user icon for a profile picture if they upload one]
- **consider** (color, all): If you want to add some pop of brand color to a nav bar, use it on the active states. Why: The source says active states are a good place to play around with brand colors if you want to add some pop. [active states are a good place to play around with your brand colors]
- **should** (components, all): Spread tab bar icons a little further apart to enlarge each click area. Why: Shifting the icons out increases the click area. [shift them out just a bit to increase our click area]
- **must** (accessibility, all): If a tab bar has text labels, make them dark enough to read. Why: The source insists on it ('for God's sake'); labels that are too light cannot be read. [for God's sake make them dark enough to read]
- **consider** (components, all): Add text labels to a tab bar when its icons are obscure; icon-only tabs suit familiar icons. Why: Whether to label depends on how obscure the icons are: the Instagram app has no labels, while apps like Apple Music do. [it just depends on how obscure your icons are]
- **should** (components, all): On a small chart that cannot be made larger, add horizontal grid lines and data markers. Why: They give the reader some clue of the fluctuations; without them the chart looks good but functionally fails. [add some horizontal grid lines and some markers]
- **must** (components, all): Do not smooth line-chart lines into curves; draw straight segments between data points. Why: The source says the curving needs to be turned off and calls it a bad trend: it makes it very difficult to tell where the tip of the line actually is. - **consider** (components, all): Do not fade out or play down the most recent data in a chart [inferred: the caption reads 'the St out', likely a fade-out]. - **should** (components, all): When a chart has room, add vertical grid lines so readers can judge the time scale. Why: They give a better sense of the time scale. [add some vertical chart lines so we can get a better sense of the time scale]
- **should** (components, all): Let people switch a chart's time frame: use a dropdown when space is short, otherwise lay the time frames out as separate options. Why: People should have the ability to switch the time frame. [we can use a drop down if we're short on space]

Why: The source assumes the button only leads to a bigger copy of the same chart, which is redundant once it is scaled up. [get rid of this button which I assume takes you to a larger version]

- **consider** (typography, all): In a card, fix the image and text margins, make the paragraph text a bit smaller and switch to a more modern font. ### Decisions it informs

- Should the tab bar show text labels under its icons? (`Q-icon-05`)
  - Icon only: No text under the icons; people must recognise each icon (the Instagram app has no labels). When: When the icons are familiar and not obscure.
  - Icons with labels: Each tab is named in text under its icon, as in Apple Music; the labels must be dark enough to read. When: When the icons are obscure.
  - Recommendation: It depends on how obscure the icons are; if labels are used, make them dark enough to read.
- Should the tab bar's add or create button stand out from the other tabs?
  - Raised circled button: A circle that sticks up above the bar and dominates it. When: The source gives no case where this is right; it only notes that the idea is to push people to add content.
  - Inline icon with an active state: The add icon sits in line with the others and gets its own active state like every other tab. When: By default.
  - Recommendation: Inline icon with an active state, because people use the other tabs most of the time.
- Should the tab bar be solid, or dark with transparency and blur? (`Q-depth-04`)
  - Solid bar: An opaque bar with clear contrast between icons and background. When: The default in the redesign.
  - Dark mode with transparency and blur: The content behind shows through a blurred, dark, see-through bar, which looks a little fancier. When: When applying the redesign back onto the original design, or to get a little fancy.
- Should line charts draw smooth curves or straight lines between data points?
  - Curved lines: A soft, flowing line that hides where each value actually sits. When: The source calls this a bad trend.
  - Straight lines: Sharp segments that show exactly where each point and the tip of the line are. When: By default.
  - Recommendation: Straight lines, because curves make it very difficult to tell where the tip of the line actually is.
- How should people switch a chart's time frame?
  - Dropdown: One compact control that hides the other time frames until opened. When: When you are short on space.
  - Separate options laid out side by side: All time frames are visible and one click away. When: When there is room.
- Should a chart include a legend?
  - Legend: A key explains each line, such as the gray previous-period line. When: Often nice to include.
  - No legend: Less clutter, relying on the reader to understand the lines. When: When the chart is intuitive enough.
  - Recommendation: A legend is often nice to include.
- Should a card have its own call-to-action button, or should the whole card be the link?
  - Whole card is the link: No button; an arrow icon fades in on hover to show the card is clickable. When: When many cards repeat over and over.
  - Explicit call-to-action button: A visible button such as 'Try it out' on the card. When: When the card has a specific call to action.
  - Recommendation: Whole-card link for repeated cards; keep the button when there is a specific action.
- Should card text sit beside or below the image, or on top of it with a gradient? (`Q-img-02`)
  - Standard card: Image and text in separate areas of the card; it always works. When: When the images and colors vary or are unknown.
  - Image with a gradient overlay: The image fills about 3/4 of the card and a smooth gradient carries the text on top, as on some Apple Music albums. When: Only with some images and colors.
  - Recommendation: The source leaves it to taste but notes the overlay card only works with some images and colors, while the standard card always works.
- How should a pricing card separate the price from the feature list?
  - Divider line: A literal line between the two areas. When: Not stated.
  - Tinted price area: The price area sits on a reduced-opacity version of the primary color, as Hostinger does. When: The source's choice.
  - Recommendation: A reduced-opacity tint of the primary color instead of a literal divider.
- Where should form field labels go? (`Q-form-01`)
  - Label as placeholder inside the input: Does not look terrible, but the label is gone once someone starts typing. When: The source calls this awful even though it does not look terrible.
  - Label above the input: The label is always visible, and the placeholder can show a real example. When: By default.
  - Recommendation: Labels above the inputs, with real example placeholders inside.
- What kind of footer should the site have?
  - Many-column footer: Several columns of links, like the footers of Apple or Linear, which look awful with only about six links. When: The source only says that more than about five links needs a different layout; it does not name which.
  - Simple centered footer: Logo above centered links, socials below, copyright on the left and design credits on the right; it also works in dark mode. When: When there are about 3 to 5 links, a pretty normal amount.
  - Recommendation: The simple centered footer for most sites, which do not need giant footers.
- How much vertical padding should a chip have?
  - Half the horizontal padding: A slightly taller chip (20 px horizontal gives 10 px vertical). When: Not distinguished by the source.
  - A quarter of the horizontal padding: A thinner, tighter chip (20 px horizontal gives 5 px vertical). When: Not distinguished by the source.
  - Recommendation: Either half or a quarter; the chip must stay thinner than a button.
- Where should a carousel's navigation sit?
  - Over the image on a dark, blurred background: Indicators and arrows sit on a dark, blurred background over the photo and stay readable on any image. When: The source's 'fancy' choice.
  - Below the image: Navigation sits under the photo, so the image never interferes with it. When: Also offered as an option.

### Process

1. Audit borrowed elements for UI and UX: When taking an element from a showcase like Dribbble, check how it works as well as how it looks: contrast, active states, click areas, labels and whether its data or controls can actually be read.
2. Upgrade a tab bar: Drop the raised add button into line, align the icons, raise contrast of inactive icons, give every tab an active state (swap the plus icon, use the profile picture), use brand color on active states, spread icons to enlarge click areas, decide on labels, and optionally make a dark, translucent, blurred version.
3. Upgrade a chart: Add horizontal grid lines and markers, straighten curved lines; if the chart can be larger, move the title, remove the 'open larger' button, add vertical grid lines, add time-frame options (a dropdown if space is short), add a gray previous-period line for business data, and add a legend.
4. Upgrade a UI card: Rewrite the text, fix the image and text margins, make the paragraph text a bit smaller, switch to a more modern font, round the corners, then decide between a whole-card link (with a hover arrow) and an explicit call-to-action button.
5. Build a gradient-overlay card: Make the image about 3/4 of the card height, overlay a smooth gradient that stretches from the bottom of the image upward, then place the text on top.
6. Upgrade a pricing card: Move the button up and make it stroke-only, use check marks for features, list a feature the plan lacks, add a plan name and description, add honest billing text, tint the price area with a reduced-opacity primary color, and make the button label actionable.
7. Make a sticker in Figma: Use the star tool with 12 points, drag out the ratio, round the corners, set a quirky display font, optionally add an outline or circular text (via a text-on-path plugin), and add a darker, full-opacity, slightly offset drop shadow.
8. Upgrade a sign-up modal: Move labels above the inputs, put real examples in the placeholders, add a 'create account' subheading, add a link to log in, add space on a 4 px grid, then give inputs an off-white fill and a 40% opacity stroke; reuse the layout for login.
9. Design a simple footer: For 3 to 5 links: center the links, put the logo above them, socials below in the center, the copyright on the left and the design credits on the right; use a different layout only if you need more than about five links.
10. Build a chip in Figma: Type the chip text, press Shift+A to wrap it in an auto layout frame, add a background, round the edges, then set vertical padding to half or a quarter of the horizontal padding.
11. Upgrade a carousel: Add indicators showing how many images there are, put them on a dark blurred background (or below the image), move the arrows beside them, and optionally turn the active indicator into a timer; the source shows it working on desktop and mobile.
