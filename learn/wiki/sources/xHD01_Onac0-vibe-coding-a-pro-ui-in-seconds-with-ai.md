# Vibe Coding a Pro UI in SECONDS With AI

## Summary

Kole Jain shows how to get a project management dashboard out of Claude with one prompt and one reference image, then pull it into Figma as an editable design. He compares reference images: busy Dribbble dashboards lose their small details because the AI cannot see them, while a screenshot of a real product such as Linear or a realistic site from SiteInspire works better. He gives a four-part prompt: say you want a design written in HTML and CSS, state the purpose and intended use, name specific elements, and require an icon library so the AI does not use emojis. He imports the downloaded HTML into Figma with the HTML to design plugin, then makes the fixes he says AI output usually needs: fonts, alignment and color, plus sidebar structure, chip contrast and honest status colors. For a design system, it gives a repeatable brief for AI-generated screens and a checklist of what to review before trusting them.

## Key Ideas

- A single prompt and one reference image can produce a well laid out dashboard, but the output still needs a design pass.
- Busy Dribbble shots make poor AI references because the AI cannot see the small details and drops them.
- A screenshot of a real product, or a realistic site from SiteInspire, gives the AI a clearer aesthetic to follow.
- Say explicitly that you want a design, and ask for HTML and CSS if the result must go into Figma.
- State the screen's purpose and intended use, because it gives the AI a lot of extra context.
- Name the specific elements you want, such as a sidebar with icons or a Gantt chart with colorful bars.
- Require an icon library in the prompt, or the AI fills the UI with emojis.
- Leave small tweaks such as a sticky sidebar or exact left alignment for Figma instead of re-prompting.
- Importing HTML rather than an image keeps every element editable and free of glitches.
- Fonts, alignment and color are the biggest fixes, and the same things that go wrong on most real websites.
- Status colors should match the state: completed-colored bars should only mean completed work.
- An actual percentage tells people more than an 'in progress' label.
- Once one screen is polished, it can serve as the reference for a landing page or the remaining screens.

### Process

1. Pick a reference image: Use your own Figma design, a realistic site from SiteInspire, or a screenshot of a real product such as Linear; avoid busy Dribbble dashboards.
2. Optionally pull AI-ready components: On 21st.dev, open a component and copy its code or its prompt, then paste it into Claude.
3. Write the prompt: Say you want a design written in HTML and CSS, state the purpose and intended use, name specific elements (sidebar with icons, Gantt chart with colorful bars), and require an icon library.
4. Generate and check: Submit with the reference image, wait a minute or two, then resize the browser to see how responsive the result is.
5. Download as HTML: In the Claude result, open the drop-down and choose download as HTML.
6. Import into Figma: Open the HTML to design plugin, switch to the File tab, drag the HTML file in, keep default settings except turning the components setting on for hover effects, and run it.
7. Polish in Figma: Fix fonts, alignment and color first, then details: sidebar structure, chip contrast, status colors that match state, percentages instead of vague labels, and missing icons.
8. Extend: Export the polished screen as an image and ask Claude for a landing page for the dashboard or the remaining screens.
